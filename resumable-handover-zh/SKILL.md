# 换窗口交接纸条

新窗口里的 AI 看不到之前任何内容，**只看这张纸条**。所以纸条要写“结论”，不写“经过”；要写“原样的名字和数字”，不写“前面提到的那个”。

## 第一步：判断场景
- **聊天**：写作、规划、改简历、学习、咨询……产物在对话里。
- **Agent**：AI 在调用工具、改文件、发东西、跑命令。
两种都按下面的格式写，Agent 多写第 7 节。

## 纸条格式（标题照抄，没内容的节写“无”）

```
【交接纸条｜<一句话说清在做什么>】
给新窗口：你是接手的助手，之前的对话你看不到，以本纸条为准。读完先用两三句话复述目标和下一步，等我确认再动手。纸条里没有的信息，问我，别猜。

1. 目标：最终要交出什么、给谁用、做到什么样算完。
2. 最终版事实：人名、数字、日期、预算、编号、确认号、文件路径、版本……原样照抄。改过口的只写新的，后面括号注明“旧的 X 已作废”。
3. 规矩：用户定的要求和禁止项，尽量用用户原话。
4. 已定稿（别再改）：哪些部分用户说定了；短的照抄原文，长的写清在哪。
5. 已作废/已取消：用户否掉的方案、删掉的情节、不去的地方、试过失败的办法（写失败原因）。新窗口不许再提议这些。
6. 还没定 / 在等别人：用户说“再想想”“先别”“等 XX 回复”的事。新窗口不许替用户决定，也不许编内容补上。
7. 结果不明的操作（Agent 必写）：发出去但没看到结果的动作（发布、提交、迁移、付款、上传）。写清去哪里查、查什么；查清之前不许重做。
8. 下一步：第一件具体要做的事（动词+对象+做完的样子）。后面几步按先后列。
```

## 写的时候
- **只写最终状态**。用户改过三次口，只留最后一次，旧说法放进第 5 节或括号里。
- **原样照抄**专有名词和数字：角色名、公司名、确认号、订单号、命令、路径、禁用词。别概括成“相关信息已确认”。
- **不写的只有秘密**：密码、验证码、银行卡号、API 密钥、身份证号。订单号、确认号、预约号、文件路径、版本号**要写**——接手的人要用。
- 闲聊、试错过程、AI 自己说过的长段内容不要抄；只留结论。
- 长度：一般 600～2000 字。宁可多写一条用户的硬规矩，也不要多写一段过程。
- 用户能看懂：不用“证据定位”“断点”“副作用”这类行话，写大白话。

## 写完自查（逐条过）
- [ ] 新窗口只看纸条，能说出第一件要做的事吗？
- [ ] 所有改过口的事，纸条里只剩新说法了吗？
- [ ] 用户否掉/取消的，都进第 5 节了吗？
- [ ] “还没定”的事，有没有被我写成“已定”？
- [ ] 结果不明的操作，有没有写成“已完成”或“未开始”？（都不对，是“待查”）
- [ ] 名字、数字、编号是不是原样？有没有把确认号当隐私删掉？

## 例子（聊天）
```
【交接纸条｜帮用户筹备 5 月 18 日的小型婚礼，在排流程和预算】
给新窗口：……（同上）
1. 目标：一份能发给婚庆和双方父母的当天流程表 + 预算表。
2. 最终版事实：日期 5 月 18 日（旧的 5 月 11 日已作废）；宾客 60 人（旧的 80 人已作废）；场地“湖畔草坪”，定金已付，合同号 HP-0518。
3. 规矩：不要中式闹婚环节；预算总额不超过 6 万；新娘妈妈不吃牛肉。
4. 已定稿：入场音乐、誓词文本（用户自己写的，别改）。
5. 已作废：室内备选场地；无人机跟拍（用户嫌贵）。
6. 还没定：要不要请乐队——等新郎问朋友报价，别替他决定。
7. 结果不明的操作：无。
8. 下一步：按 60 人重算餐费，更新预算表。
```

## 例子（Agent）
```
7. 结果不明的操作：执行了 deploy.sh 发布 v2.3 到测试服，SSH 断开，不知道成没成。先打开 /health 看版本号是不是 2.3；查清前不许再跑 deploy.sh。
8. 下一步：查 /health 版本号；确认后改 config/cache.yml 的过期时间为 600，跑 npm test -- cache。
```
