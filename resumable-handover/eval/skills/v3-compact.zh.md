---
name: resumable-handover
description: 当任务需要暂停、换班或转交且必须保留执行断点时使用。
---
## IO
输入：目标、当前事实、证据、未完成项、未知动作。
输出：可恢复断点单；不执行剩余动作。
缺证据：标缺失，不编造完成。
停止：接手者可确定第一动作而无需重查全史。
## RULES
1. 分开目标与现状。
目标写最终可见状态。
现状只写已观察事实。
两者差距限定剩余工作。
2. 关闭已完成项。
每项附证据定位。
附观察时间或版本。
保留证据实际支持的结论。
不让已解决项漂成待办。
3. 排序未完成项。
每项写动作、输入、完成信号。
按依赖而非聊天时间排序。
独立可做项放在等待项之前。
4. 单列未知副作用。
记录原请求非敏感标识。
记录目标、时间窗、内容指纹。
下一动作只能查询或等待。
不能改标未开始。
5. 记录变更与恢复。
写修改对象与旧版定位。
写触发恢复的条件。
无备份就写无，不能虚构。
6. 标证据失效条件。
稳定文件结果不机械重验。
环境变化只影响对应事实。
短索引指向长证据具体字段。
7. 写第一动作。
用动词、对象、完成信号。
核心下一步不得藏在附件。
没有可做项则写具体等待事件。
## IF/THEN
IF 全部完成 THEN 不制造待办。
IF 已取消 THEN 不保留可执行旧动作。
IF 当前暂停 THEN 不暗示自动恢复。
IF 原结果未知 THEN 保留原查询线索。
IF 证据缺失 THEN 标无法独立验证。
IF 版本变化 THEN 指明受影响结论。
## MUST
目标与当前结果。
范围与禁止项。
完成项及证据。
未完成项及依赖。
未知动作与查询条件。
变更恢复与第一动作。
## NEVER
复制完整过程聊天。
写凭据或私人记录。
把保存交接当业务完成。
用继续优化充当下一步。
## CHECK
接手者能找到材料。
接手者能区分已发生动作。
取消与暂停不会被误执行。
首个动作可直接执行。
## BAD→GOOD
BAD：差不多了，继续做。
GOOD：内容已核；下一步重开派生文件检查页尾。
